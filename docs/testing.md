# Validation and Testing

Testing is split into two phases: Software Validation (currently implemented) and Hardware Validation (planned).

## Software Validation

Unit tests have been implemented to guarantee the mathematical and cryptographic integrity of the core system components. These tests are written in Python and are executed using `pytest`.

### 1. Protocol Verification (`tests/test_beacon_schema.py`)
This test validates the `BeaconPacket` struct packing and CRC-16 calculation.
*   **Methodology**: Packs a test struct using Python's `struct` module and calculates the CRC-16 CCITT-FALSE using the `crcmod` library.
*   **Validation**: Confirms that the resulting byte array identically matches the output generated by the C++ firmware on the ESP32.

### 2. Coordinate Translation (`tests/test_translator.py`)
This test verifies the accuracy of the tangent-plane mathematics used to convert local SLAM coordinates to global coordinates.
*   **Methodology**: Mocks a GNSS anchor location and passes local East-North-Up (ENU) coordinates.
*   **Validation**: Asserts that the resulting WGS84 Latitude and Longitude match the expected offsets calculated using Haversine distance functions.

## Hardware Validation (Planned)

Physical validation tests on the hardware are planned for the upcoming competition phases:
*   **RF Range and Interference Testing**: Validating the 868MHz LoRa mesh in a simulated rubble environment.
*   **SLAM Accuracy**: Measuring odometry drift during continuous operation in feature-poor environments.
*   **Autonomous Homing**: Validating the Executor Robot's ability to navigate using RSSI gradients from deployed beacons.
